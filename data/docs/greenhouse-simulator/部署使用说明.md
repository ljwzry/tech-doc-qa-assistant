## 1. 项目简介

冬枣种植智慧大棚物联网平台是一个集环境监测、数据采集、智能预警与 AI 对话分析于一体的全栈智慧农业解决方案。

**核心组件：**

| 组件 | 技术栈 | 说明 |
|------|--------|------|
| **后端** | Java Spring Boot 4.x + MyBatis | 若依框架 (RuoYi-Vue v3.9.2) 二次开发 |
| **前端** | Vue 2.x + Element UI | 门户 + 管理后台 |
| **AI 胶水层** | Python | Gateway + MCP Server + MQTT Bridge |
| **AI Agent** | nanobot | MCP tool-calling + 多轮对话 + SSE 流式输出 |
| **知识图谱** | Neo4j | 冬枣种植病虫害/物候期/药剂结构化知识 |
| **数据库** | PostgreSQL + TDengine | 业务数据 + 时序数据 |
| **缓存** | Valkey (Redis) | JWT token 存储、缓存 |
| **消息** | Mosquitto MQTT | 传感器数据通信 |

## 2. 系统架构

### 2.1 整体架构图

```
浏览器 (:17000) ──→ Nginx ──┬── /prod-api/* ──→ Java Backend (:17001)
                            │                        │
                            └── /api/chat ──→ Gateway (:17003) ──→ nanobot (:17002)
                                                     │                │
                            ┌────────────────────────┘                │
                            │                                  MCP Protocol
                            ▼                                         │
                     MCP Server (:17004) ←────────────────────────────┘
                            │
                     ┌──────┼──────┐
                     ▼      ▼      ▼
                  Backend  Redis  Neo4j
                    :8080  :6379  :7687

  MQTT 传感器 ──→ Mosquitto (:17013) ──→ MQTT Bridge ──→ nanobot ──→ Gateway ──→ WS 推送
```

### 2.2 服务组件说明

| 层 | 组件 | 默认端口 | 说明 |
|----|------|---------|------|
| 前端 | Nginx + Vue | **17000** | 门户前端 |
| 前端 | Nginx + Vue2 | **17005** | 若依管理后台 |
| 后端 | Java Spring Boot | **17001** | REST API, JWT HS512 鉴权, 数据持久化 |
| AI | nanobot | **17002** | MCP tool-calling, SSE 流式对话 |
| 胶水 | Gateway | **17003** | 聊天代理, WebSocket 推送, 定时任务 |
| 胶水 | MCP Server | **17004** | 35 个物联网工具, 知识图谱查询 |
| 胶水 | MQTT Bridge | — | 传感器数据 → AI 分析 → 推送 |
| 基础设施 | PostgreSQL | **17011** | 业务数据 + PostGIS 空间扩展 |
| 基础设施 | Valkey | **17012** | 缓存 / Session / JWT token |
| 基础设施 | Mosquitto | **17013** | MQTT Broker |
| 基础设施 | TDengine | **17014** | 时序数据 (HTTP REST API) |
| 基础设施 | Neo4j | **17015-17016** | 知识图谱 (Bolt + HTTP) |

### 2.3 数据流

1. **用户对话流**：浏览器 → Nginx → Gateway (JWT 鉴权) → nanobot (AI 推理) → MCP Server (工具调用) → Java Backend (数据查询) → 响应流式返回
2. **传感器数据流**：传感器 → MQTT → Mosquitto → MQTT Bridge → nanobot (AI 分析) → Gateway → WebSocket → 用户
3. **定时任务流**：Gateway Scheduler → nanobot → MCP Server → Backend → Gateway → WebSocket 推送

## 5. 快速部署（一键脚本）

### 5.1 全栈部署（推荐）

```bash
# 交互模式 — 脚本会询问所有配置
bash deploy/deploy.sh

# 非交互模式 — 通过环境变量预置所有参数
export LLM_PROVIDER=deepseek
export LLM_API_KEY=sk-xxx
export LLM_MODEL=deepseek-v4-flash
export LLM_BASE_URL=https://api.deepseek.com
export DB_PASSWORD=MySecurePass
bash deploy/deploy.sh --yes
```

### 5.2 部署流程（9 阶段）

脚本会自动执行以下步骤：

1. **环境检测** — 检查 Docker、Java、Maven、Node.js 等
2. **交互配置** — 收集 LLM、数据库、安全等配置
3. **启动基础设施** — PostgreSQL + Valkey + TDengine + Mosquitto + Neo4j
4. **构建 Java 后端** — Maven 打包
5. **构建前端** — npm 构建 Vue2/Vue3
6. **配置 nanobot** — 生成配置文件并构建镜像
7. **构建胶水层镜像** — Gateway + MCP Server + MQTT Bridge
8. **全栈启动** — 按顺序启动所有服务
9. **服务验证** — 健康检查

### 5.3 常用部署选项

```bash
# 跳过 Maven 构建（JAR 已存在）
bash deploy/deploy.sh --skip-build

# 跳过前端构建（服务器不构建前端）
bash deploy/deploy.sh --skip-frontend

# 跳过基础设施（已手动启动）
bash deploy/deploy.sh --skip-infra

# 选择前端版本
bash deploy/deploy.sh --frontend=vue3   # 默认
bash deploy/deploy.sh --frontend=vue2

# 选择前端构建方式
bash deploy/deploy.sh --frontend-build=auto   # 自动检测
bash deploy/deploy.sh --frontend-build=local  # 本地 npm
bash deploy/deploy.sh --frontend-build=docker # Docker 构建

# 停止并清理所有容器（含数据库 volume）
bash deploy/deploy.sh --clean
docker volume rm dongzao_postgres-data  # 彻底清理数据
```

## 6. 分步部署

### 6.1 启动基础设施

```bash
# 启动所有基础设施
docker compose up -d

# 查看状态
docker compose ps

# 停止
docker compose down
```

### 6.2 构建 Java 后端

```bash
# 从项目根目录构建
mvn clean package -DskipTests -pl backend/ruoyi-admin -am

# 或使用 Docker 构建
docker run --rm -v "$(pwd):/app" -w /app \
  maven:3.9-eclipse-temurin-17 \
  mvn clean package -DskipTests -pl backend/ruoyi-admin -am

# 运行后端
java -jar backend/ruoyi-admin/target/ruoyi-admin.jar \
  --spring.profiles.active=prod,druid
```

### 6.3 启动 nanobot

```bash
# 从源码构建
docker build -t dongzao-nanobot:latest nanobot-main/

# 运行
docker run -d --name nanobot \
  -p 17002:8900 \
  -v deploy/nanobot-config/config.json:/home/nanobot/.nanobot/config.json \
  --network dongzao \
  dongzao-nanobot:latest serve --verbose
```

### 6.4 启动胶水层

```bash
# 方式一：Docker Compose
docker compose -f deploy/docker-compose.glue.yml up --build

# 方式二：本地开发模式
cd services/mcp-server && MOCK_DONGZAO=1 MCP_TRANSPORT=sse MCP_PORT=17004 python server.py
cd services/gateway && python main.py
cd services/mqtt-bridge && python bridge.py
```

### 6.5 启动前端

```bash
# 方式一：Docker Compose（需要 dist 目录存在）
docker compose -f deploy/docker-compose-full.yml up -d dongzao-ui

# 方式二：本地开发
cd backend/ruoyi-ui && npm install && npm run dev

# 方式三：构建后部署
cd dongzao_UI/RuoYi-Vue3 && npm install && npm run build:prod
# 然后将 dist 目录挂载到 Nginx
```

### 6.6 仅启动应用层（需先启动基础设施）

```bash
docker compose -f deploy/docker-compose-full.yml up --build
```

### 10.9 写操作安全机制

所有写操作使用 **token-gated 二次确认**机制：

1. 首次调用返回确认 token（有效期 5 分钟）
2. 用户同意后携带 token 再次调用才生效
3. Token 单次使用，存储在内存中
4. LLM 无法绕过此机制

## 11. 数据库说明

### 11.1 PostgreSQL（业务数据）

- **数据库**：ry-vue
- **用户**：postgres

- **初始化脚本**：

## 14. 常见问题与排查

### 14.1 后端启动报 `relation "xxx" does not exist`

**原因**：PostgreSQL initdb 脚本执行中断，通常是旧 volume 残留导致。

**解决**：
```bash
docker compose down
docker volume rm dongzao_postgres-data
bash deploy/deploy.sh
```

### 14.2 nanobot 反复重启 / `No API key configured`

**原因**：nanobot 配置文件格式不兼容。

**排查**：检查 `deploy/nanobot-config/config.json`：
- provider 名必须是注册表中的名称（`deepseek`/`openai`/`custom` 等）
- 不能是 `openai_compat`
- 不要包含 `systemPrompt` 等非 schema 字段

**解决**：
```bash
# 重新生成配置
bash deploy/deploy.sh

# 查看 nanobot 日志
docker logs nanobot | tail -50
```

### 14.3 AI 回复"没有找到大棚数据"

**原因**：MCP 工具未被加载。

**排查**：
```bash
docker logs nanobot | grep -i mcp
```

如果出现 `blocked unsafe URL`，说明 SSRF 保护拦截了 Docker 内网地址。

**解决**：在配置 `tools.ssrfWhitelist` 中添加 `["172.16.0.0/12"]`（已在配置中预置）。

### 14.4 Gateway 返回 401 / token 签名无效

**原因**：JWT_SECRET 不一致或浏览器缓存了旧 token。

**解决**：
- 确认 `deploy/.env` 中的 `JWT_SECRET` 与后端一致
- 重新登录获取新 token

### 14.5 端口被占用

**解决**：
```bash
# 查找占用端口的进程
netstat -tlnp | grep 17001

# 修改端口配置
export BACKEND_PORT=18001
bash deploy/deploy.sh
```

### 14.6 Docker 网络冲突

**解决**：
```bash
# 清理旧网络
docker network rm dongzao 2>/dev/null || true

# 重新部署
bash deploy/deploy.sh
```

### 14.7 Maven 构建失败

**排查**：
```bash
# 查看构建日志
cat deploy/logs/maven_build.log

# 常见原因：
# 1. Java 版本不匹配（需要 JDK 17+）
# 2. Maven 依赖下载失败
# 3. 代码编译错误
```
