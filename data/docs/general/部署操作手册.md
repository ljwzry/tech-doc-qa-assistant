## 1. 项目简介

技术文档问答助手是一个基于 RAG（检索增强生成）架构的智能问答系统，支持：

- 多项目知识库管理（按文件夹隔离）
- 混合检索（Chroma 向量 + BM25 关键词 + RRF 融合）
- LangGraph ReAct Agent 智能工具调用
- SSE 流式聊天响应
- 会话持久化（刷新页面保留对话）
- 网络搜索兜底（百度 + DuckDuckGo）

## 4. 配置说明

### 4.1 创建环境配置文件

在项目根目录下创建 `.env` 文件：

```bash
# Windows
New-Item -Path ".env" -ItemType File
# Linux/macOS
touch .env
```

### 4.2 .env 配置项

```ini
# ============ LLM 配置 ============

# 方案 A：SiliconFlow 中转平台（推荐，国内可访问、性价比高）
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-your-siliconflow-api-key
DEEPSEEK_BASE_URL=https://api.siliconflow.cn/v1
LLM_MODEL=deepseek-ai/DeepSeek-V3

# 方案 B：DeepSeek 官方 API
# LLM_PROVIDER=deepseek
# DEEPSEEK_API_KEY=sk-your-deepseek-api-key
# DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
# LLM_MODEL=deepseek-chat

# 方案 C：Ollama 本地模型（完全离线，需先安装 Ollama）
# LLM_PROVIDER=ollama
# OLLAMA_BASE_URL=http://localhost:11434
# LLM_MODEL=qwen2.5:7b

# ============ Embedding 配置 ============

# BGE-small-zh（约 100MB，纯 CPU 环境速度快，推荐）
EMBEDDING_MODEL=BAAI/bge-small-zh
EMBEDDING_DEVICE=cpu
# CPU 线程数（建议设为物理核心数的一半）
EMBEDDING_THREADS=8

# 如有 GPU 可改用（约 2GB，效果更好）：
# EMBEDDING_MODEL=BAAI/bge-m3
# EMBEDDING_DEVICE=cuda

# ============ 数据存储配置 ============

# Chroma 向量数据库持久化目录
CHROMA_PERSIST_DIR=./data/chroma_db

# ============ 应用配置 ============

APP_HOST=0.0.0.0
APP_PORT=8000
```

### 4.3 获取 API Key

| 平台 | 注册地址 | 说明 |
|------|----------|------|
| SiliconFlow | https://siliconflow.cn | 推荐，国内可访问，注册送额度 |
| DeepSeek | https://platform.deepseek.com | 官方 API，价格低 |

## 6. Docker 部署

### 6.1 确认配置

确保项目根目录已存在 `.env` 文件（参见第 4 节）。

### 6.2 一键启动

```bash
cd tech-doc-qa-assistant

# 构建镜像并启动服务（后台运行）
docker-compose up --build -d
```

首次启动会：
1. 拉取 `python:3.11-slim` 基础镜像
2. 安装 Python 依赖
3. 下载 BGE-small-zh 模型（约 100MB，缓存到 `data/model_cache/`）
4. 启动后端（8000）和前端（8501）

### 6.3 查看容器日志

```bash
# 查看后端日志
docker-compose logs -f backend

# 查看前端日志
docker-compose logs -f frontend
```

### 6.4 Docker Compose 配置说明

| 配置项 | 说明 |
|--------|------|
| `volumes: ./data:/app/data` | 挂载数据目录（文档、索引、向量库） |
| `volumes: ./data/model_cache:/app/data/model_cache` | 挂载模型缓存（避免重建容器时重下模型） |
| `volumes: ./.env:/app/.env` | 挂载环境配置 |
| `environment: TRANSFORMERS_CACHE` | 指定 HuggingFace 缓存路径 |
| `restart: unless-stopped` | 容器异常退出自动重启 |

### 6.5 更新与重建

```bash
# 拉取最新代码后重建
docker-compose up --build -d

# 仅重启（不重建镜像）
docker-compose restart
```

## 8. 停止与重启服务

### 8.1 停止服务

**本地开发模式**：

Windows (PowerShell)：
```powershell
# 按端口查找并停止进程
Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
Get-NetTCPConnection -LocalPort 8501 -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

Linux / macOS：
```bash
# 按端口查找并停止
lsof -ti:8000 | xargs kill -9
lsof -ti:8501 | xargs kill -9
```

**Docker 模式**：
```bash
docker-compose down
```

### 8.2 重启服务

**本地开发模式**：

Windows (PowerShell)：
```powershell
# 1. 停止旧服务
Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
Get-NetTCPConnection -LocalPort 8501 -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
Start-Sleep -Seconds 2

# 2. 启动后端
Start-Process -FilePath python -ArgumentList "-m","uvicorn","app.main:app","--host","0.0.0.0","--port","8000" -WindowStyle Hidden

# 3. 等待后端就绪
Start-Sleep -Seconds 10

# 4. 启动前端
Start-Process -FilePath python -ArgumentList "-m","streamlit","run","frontend/app.py","--server.port","8501","--server.headless","true" -WindowStyle Hidden
```

**Docker 模式**：
```bash
docker-compose restart
```

## 10. 常见问题排查

### 10.1 端口被占用

**现象**：启动时报 `Address already in use` 或 `[WinError 10061]`

**解决**：
```powershell
# Windows: 查找占用 8000 端口的进程
Get-NetTCPConnection -LocalPort 8000 | Select-Object OwningProcess
Stop-Process -Id <PID> -Force

# Linux/macOS
lsof -i :8000
kill -9 <PID>
```

### 10.2 模块导入失败

**现象**：`ModuleNotFoundError: No module named 'xxx'`

**解决**：
```bash
# 确保已激活虚拟环境
# Windows
.\.venv\Scripts\Activate.ps1
# Linux/macOS
source .venv/bin/activate

# 重新安装依赖
pip install -r requirements.txt
```

### 10.3 Embedding 模型下载失败

**现象**：首次启动卡在 `正在加载 Embedding 模型` 或报网络错误

**解决**：项目已配置 HuggingFace 镜像源（`https://hf-mirror.com`）。如仍失败：
```bash
# 手动预下载模型到缓存目录
pip install huggingface-hub
huggingface-cli download BAAI/bge-small-zh --local-dir ./data/model_cache/BAAI_bge-small-zh
```

### 10.4 LLM API 报 401/403

**现象**：调用聊天 API 返回认证错误

**解决**：
1. 检查 `.env` 文件中 `DEEPSEEK_API_KEY` 是否正确
2. 确认 API Key 未过期且有余额
3. 确认 `DEEPSEEK_BASE_URL` 与 API Key 所属平台匹配

### 10.5 LLM API 报 503

**现象**：`System is too busy now` 或 503 Service Unavailable

**解决**：这是 LLM 服务端的临时过载，稍后重试即可。或切换到 Ollama 本地模型方案（参见第 4 节方案 C）。

### 10.6 文档上传后检索不到

**现象**：上传文档后提问，Agent 回答"未找到相关信息"

**解决**：
1. 确认文档格式为 `.md` / `.txt` / `.pdf`
2. 确认上传时指定了正确的 `project` 参数
3. 提问时尝试包含项目名（如"项目A 的 xxx"）或文档名（如"README.md 里讲了什么"）
4. 检查文档内容是否为空或过短（少于 100 字符可能无法有效切分）

### 10.7 Docker 容器重启后模型重新下载

**现象**：`docker-compose down` 后再 `up`，Embedding 模型重新下载

**解决**：确认 `docker-compose.yml` 中已挂载 `model_cache` 卷：
```yaml
volumes:
  - ./data/model_cache:/app/data/model_cache
```

### 10.8 前端页面空白

**现象**：访问 http://localhost:8501 显示空白页

**解决**：
1. 确认后端服务已启动（`http://localhost:8000/health` 返回 200）
2. 检查浏览器控制台是否有 CORS 错误
3. 确认 `.env` 配置正确，API Key 有效
4. 查看后端日志是否有异常
